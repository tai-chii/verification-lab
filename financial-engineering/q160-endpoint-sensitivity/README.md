# Q354 Q160 の確定は評価期間の端点を ±1 年ずらした 9 通りで何通り保たれるか（方法論・確定判定の端点感度）

事前登録: スクリプト `kensho_q354.py` の docstring（2026-10-20 Opus）。出所: 接続ログ 2026-10-20 Q352-C2（hiro_algo の Zenn「2007年と2013年を足すと Short 優位も 0 をまたぐ」× 改善判定「期間別を同時に見ればどこか1セルは偶然有意」）。元の検証: [[../long-short-decomposition/README|Q160]]。

- データ: トレンド6（XAU/XAG/WTI/UKOIL/US500/USTECH）D1_fromH1、2008-02〜2026-07。
- 方法: データを窓（開始 2008/2009/2010-01-01 × 終了 2024/2025/2026-12-31）で切り、Q160 の関数をそのまま使ってドンチャン55/20 の買い側ドリフト除去後 [bp/足] と、半年ごとの日時共通並べ替え帰無（B=500・seed=20261009）の z を出す。群ごとに z≥2 のセル数 K を数える。
- 判定（事前固定）: 群ごとに K=9 頑健／7〜8 未確定／≤6 端点依存。総合は悪い方の群で決める。
- 実行: `python3 kensho_q354.py`（全9セル・1セル約20秒）→ `python3 kensho_q354.py --aggregate`
- 結果: `results/Q354_cell_<開始>-<終了>.json`・`results/Q354_result_20261020_101407.json`・`results/Q354_run_B500.log`

- トレンド6: K=3/9 → **端点依存**（z 最小 1.68）。z≥2 は終了 2026 の3セルだけ。終了 2025 と 2026 の差は **2026年1〜7月の約半年分だけ**で、それで平均が +0.57→+0.78bp、z が 1.8→2.4 に跳ぶ。開始年は効かず、終了年（最新の半年）が効く。
- 商品4: K=9/9 → **頑健**（z 最小 2.08）。ただし終了 2024・2025 では z 2.1〜2.2 で閾値のすぐ上。
- 売り側ドリフト除去後は 18 セルすべて |z|<0.7（Q160 の「売り側は 0」は端点にも頑健）。
- 注意: 終了の「+1年」はデータが 2026-07 で切れるため存在しない。終了側は実質 0／−1／−2 年（非対称）。9 セルは期間が大きく重なり独立ではない。K は検定ではなく「端点を振ったときに閾値をまたぐ数」。

判定: **確定**
