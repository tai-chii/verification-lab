- 解釈時の確認（コード点検の宿題）: 腕 Y は平均 +0.048R・日次 t 4.51 で、これまでの S21 WF（Q534 E1: +0.046R・t 4.72）とほぼ一致 → pandas 回避の副作用はないと見る。

## コードの点検（Opus・2026-10-27 17:50・実行中に・結果を見る前）

事前登録と `kensho_s21_trainwin_q555.py` を突き合わせた。**直すところはなし**。
- 学習: `train_win` は `Q.train_window` と同じ（決済が s0 より前の行だけ）。窓の始まりは `s0 − N か月`、WX は拡大窓。攻めた設定は `dict(K.LGB_PARAMS, min_child_samples=50)`・step 1。
- 閾値: 腕ごとに学習外の予測を月でつなげ、`J.thr_series` を当てている（2016-09 は閾値用だけ・売買は 2016-10 以降）。Y は毎年 10-01 に拡大窓で学習。
- 売買・物差し: `K.run_policy(…, 0.0)`・`E.block(PP, dataw, 1)` は見本 `run_q546.py` と同じ。日次 t の `K.daily` は 2026-10-25 の土日修正が入った版。月次 R は入った足の月。Δ は片側 t・Holm 8 本。判定の文は事前登録と同じ。
- 小さな注意（判定は変えない）: 2025-09 の最後の週に入った売買は、決済に 2025-10-01〜03 の値を使う（週末前決済で最長でも 10-03 まで）。この期間は Q527 で開封済みなので、封印の問題ではない。
- pandas 2.3 の回避（`_compat_tz_to_numpy`）は tz つきの時刻を UTC の datetime64 にするだけ。**解釈のときの確認**: 腕 Y（今の運用の再現）の 1 件あたり R・日次 t が、これまでの S21 の WF（毎年学習し直し）と大きく食い違わないこと（閾値の作り方が違うので完全一致はしない）。大きく違えば、回避の副作用を疑う。
